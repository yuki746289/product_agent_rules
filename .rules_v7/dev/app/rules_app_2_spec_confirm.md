## 仕様書の確認

プロジェクト直下の `.document` フォルダに作成した `仕様_差分_v{n}.{m}.md` および `仕様_全体_v{n}.{m}.md` を確認して下さい。
この工程では仕様書だけを確認し、要件定義書、設計書、コードとの突合せは行いません。

### 1. ファイル配置チェック

- [ ] `.document/仕様_差分_v{n}.{m}.md` が存在すること。
- [ ] `.document/仕様_全体_v{n}.{m}.md` が存在すること。
- [ ] 仕様書がコード別またはバージョン別成果物フォルダに作成されていないこと。
- [ ] 前バージョンの `仕様_全体_v{prev}.md` を参照していること。

### 2. 差分仕様チェック

- [ ] 前バージョンからの追加、変更、削除、維持が区別できること。
- [ ] 各変更に仕様ID、変更区分、変更前後、変更理由、影響範囲および全体仕様との対応が記載されていること。
- [ ] ユーザの開発指示が漏れなく仕様化されていること。
- [ ] 未決事項や曖昧な記述が残っていないこと。

### 3. 全体仕様チェック

- [ ] 前バージョンの全体仕様を全文継承していること。
- [ ] 章、文章、表、例、注意点が理由なく欠落していないこと。
- [ ] 差分仕様が全体仕様の該当箇所へ統合されていること。
- [ ] 差分仕様と全体仕様に矛盾がないこと。
- [ ] 仕様書内の各記述に相互矛盾がないこと。
- [ ] 主要な仕様項目と受け入れ条件に、重複しない安定した仕様IDが付与されていること。
- [ ] 開発対象に関する「未確定」または「要確認」が残っていないこと。
- [ ] 未決定の設計事項が仕様上の確定事項として記載されていないこと。
- [ ] 対象ファイルを更新日時だけで決定していないこと。

### 4. 確認結果

確認結果は、プロジェクト直下の `.document/仕様確認_v{n}.{m}.md` に出力して下さい。
不備がある場合は `rules_app_1_spec.md` に戻って仕様書を修正し、再確認して下さい。
すべての確認が完了した場合のみ、手順3へ進んで下さい。
