# product_agent_rules

AI エージェント向けの開発・確認ルールを管理するためのリポジトリです。

複数バージョンの `.rules_*` ディレクトリを保持し、別プロジェクトでは必要なルールセットを `.rules` として取り込んで利用します。

## 使用準備

### 手順1. 取り込み先プロジェクトへルールを配置する

別プロジェクトへ取り込む場合は、`pull_rules.sh` を実行してください。

最新版の `.rules_v7` が、取り込み先リポジトリでは `.rules` という名前で配置されます。

### 手順2. AI エージェント用の指示を追加する

取り込み先プロジェクトの `AGENTS.md` など、AI エージェントが参照する指示ファイルには、以下を追加してください。

```markdown
- 開発ルール
  - 開発を行う場合、必ず`.rules/dev/rules_dev.md`を確認すること。
```

プロジェクト固有のルールは `.rules/dev/rules_dev_custom.md` に記載します。デフォルトは空です。`pull_rules.sh` でルールを更新しても、取り込み先にあるこのファイルの内容は保持されます。

## 使用方法

### 簡単な使用例

開発を依頼する前に、通常開発または簡易開発を選びます。
v7 の通常開発では、最初に仕様書を作成・確認し、その後に要件定義、設計、実装、最終確認を行います。

- `app`: アプリケーション向けの通常開発ルールです。仕様作成から実装後の最終確認までを扱います。
- `batch`: バッチ処理やスクリプト向けの通常開発ルールです。仕様作成から実装後の最終確認までを扱います。
- `class`: クラス設計向けの通常開発ルールです。現在作成中のため、利用時は内容を確認してください。
- `quick_fix`: 既存仕様を変更しない軽微な修正向けの簡易開発ルールです。仕様変更や仕様書修正が必要な場合は使用できません。

依頼例:

```text
.rules/dev/rules_dev.md を確認してから進めてください。
今回は app ルールを使用します。
対象は sample_app です。
○○を作成したいです。
```

## ディレクトリ構成

```text
.rules_v1/
.rules_v2/
.rules_v3/
.rules_v4/
.rules_v5/
.rules_v6/
.rules_v7/
pull_rules.sh
```

- `.rules_v1`: 初期版のルールセット
- `.rules_v2`: v2 のルールセット
- `.rules_v3`: v3 のルールセット
- `.rules_v4`: v4 のルールセット
- `.rules_v5`: v5 のルールセット
- `.rules_v6`: v6 のルールセット
- `.rules_v7`: 最新版のルールセット
- `pull_rules.sh`: 他リポジトリから最新版の `.rules_v7` を取り込むスクリプト

## ルールの取り込み

取り込み先のリポジトリで `pull_rules.sh` を実行します。

```bash
bash ./pull_rules.sh
```

既定では `yuki746289/product_agent_rules` から取得します。

### 取り込み対象

スクリプトを実行すると、取得元リポジトリにある `.rules_v7` の各項目が `.rules` へ配置されます。

```text
.rules_v7/* -> .rules/*
```

### 上書き確認

取り込み先に同名のファイルまたはディレクトリがある場合は、項目ごとに置換確認メッセージが表示されます。

```text
Replace '.rules/dev'? [y/yes/n/no]:
```

`y` または `yes` を入力すると、対象項目を削除してから `.rules_v7` の同名項目をコピーします。

`n` または `no` を入力すると、その項目をスキップして次の項目へ進みます。

### 注意

- `.rules` 直下の項目単位で置換されます。
- 取得元に存在しないローカル専用項目は保持されます。
- 置換をスキップした項目には、旧バージョンのファイルが残る場合があります。
- 取り込み後は `git status --short` や `git diff --stat` で差分を確認してください。
