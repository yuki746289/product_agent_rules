## 運用ルール

- 作業開始時に本ファイルを案件の成果物フォルダへコピーする。
- 該当しない項目は`N/A（理由）`と記録する。
- 未確認、未完了またはNGが1件でも残る場合、該当工程および最終確認をPASSにしない。

## 1. 手順1〜2 仕様・基準

- [ ] 対象画面、操作、処理、入力規模および実行環境を特定した。
- [ ] 起動、初期表示、操作応答、処理時間およびメモリの適用対象を判定した。
- [ ] 測定開始点、終了点、回数、データ、ウォームアップおよび統計値を定義した。

- [ ] 基準値と性能目標を実測値で記録した。未計測の場合は明記した。

## 2. 手順3〜5 分析・基本設計

- [ ] profilerまたは処理内訳でボトルネックを特定した。
- [ ] 起動、読込、変換、描画、通信および保存を分けて測定した。
- [ ] キャッシュ、遅延読込、事前計算、差分更新、非同期処理およびデータ量削減を比較した。
- [ ] キャッシュのキー、有効期間、無効化、容量上限および復旧を設計した。
- [ ] UIスレッドを占有しない構成と、処理中、取消し、失敗および再試行を設計した。
- [ ] 採用案と不採用案の効果、複雑性、メモリおよびリスクを記録した。

## 3. 手順6〜8 詳細設計・実装

- [ ] 対象関数、イベント、API、クエリ、ファイルおよびデータフローを特定した。

- [ ] 競合、取消し、終了処理およびキャッシュ不整合を設計した。
- [ ] Python対象ではapp用Python規約を全文確認し、適用結果を記録した。
- [ ] 承認範囲外の全面書換え、不要な依存追加または安全処理の省略がない。

## 4. 手順9 測定・回帰確認

- [ ] 同一環境、入力、操作および測定条件で変更前後を比較した。
- [ ] 原則3回以上測定し、中央値、ばらつき、ピークメモリおよび処理内訳を記録した。
- [ ] 起動、主要操作、最大データ、0件、境界、異常、取消し、再試行および終了を確認した。
- [ ] 機能、URL、データ、UI、エラーおよびセキュリティに未承認差異がない。
- [ ] UI対象では指定画面幅と状態を実画面で確認した。
- [ ] 目標未達または悪化した指標を記録した。

- [ ] 実際の起動・配布方法と本番相当データで最終測定した。
