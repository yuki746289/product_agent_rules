# 簡易修正 手順1: 修正内容の要件

作成日時: 2026-05-19 08:03:22

## 目的

  簡易修正で行う修正内容、対象ファイル、影響範囲を整理します。
  修正内容が簡易修正として扱える範囲か確認します。
  また、修正内容が実装可能な内容であることを確認します。

## 参照ルール

  - `.rules/rules_common.md`
  - `.rules/dev/rules_dev.md`
  - `.rules/dev/quick_fix/rules_quick_fix_1_request.md`

## 入力

  - ユーザから提示された修正内容
  - 修正対象のコードファイル
  - 直前バージョンまたは直前リビジョンの成果物
  - 必要に応じて既存仕様書

## 出力

  `{filename}_v{n}.{m}_1_request.md`

## 作成内容

  以下を記述します。

  - 修正概要
  - 修正対象ファイル
  - 修正理由
  - 現在の問題点
  - 修正方針
  - 影響範囲
  - 実装可能性
  - 簡易修正として扱う理由
  - 通常開発手順に切り替える必要がない理由
  - 動作確認方針
  - ユーザ確認事項

## 簡易修正として扱える条件

  以下に該当する場合は、簡易修正として扱ってよいです。

  - 軽微な修正である
  - 既存仕様の範囲内の不具合修正である
  - 文言修正である
  - ログ修正である
  - コメント修正である
  - 既存処理の小規模な条件変更である
  - 新規機能追加ではない
  - 入出力仕様を大きく変更しない
  - 処理フローを大きく変更しない
  - 実装可能な内容であることを確認できる

## 通常開発へ切り替える条件

  以下に該当する場合は、簡易修正を中止し、ユーザに報告します。

  - 新機能追加が必要な場合
  - 基本設計の変更が必要な場合
  - 詳細設計の変更が必要な場合
  - 複数機能に大きく影響する場合
  - 入力仕様、出力仕様、DB仕様、ファイル仕様が大きく変わる場合
  - 既存の `[KEEP]` ロジックに影響する場合
  - 修正範囲が不明確な場合
  - 実装可能な内容であることを確認できない場合

## 実装可能性の確認

  以下を確認します。

  - 修正対象ファイルが存在すること
  - 修正対象箇所を特定できること
  - 既存の処理構造で実装できること
  - 必要な入力情報が揃っていること
  - 追加で必要なファイルや仕様がないこと
  - 修正後の動作確認方法を定義できること

## 注意事項

  - 作業開始前に、参照ルールと参照ファイルを提示すること。
  - 修正対象ファイルを明記すること。
  - 影響範囲を推測で断定しないこと。
  - 実装可能な内容であることを確認すること。
  - 不明点や矛盾がある場合は作業を停止し、ユーザに確認すること。
