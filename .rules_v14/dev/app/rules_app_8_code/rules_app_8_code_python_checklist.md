# app Pythonコード実装規約チェックリスト

## 1. 使用方法

- Pythonコードを作成、変更またはレビューする前に、本ファイルを対象案件の成果物フォルダへコピーして使用して下さい。
- 各項目へ`対象 / 対象外 / 未確認`、`OK / NG / N/A`および確認根拠を記録して下さい。
- 対象外には理由を記録し、未確認またはNGが1件でもある場合は手順8・9・10を合格にしてはいけません。
- 再修正した場合は、再修正差分と影響範囲について確認をやり直して下さい。

## 5. 目視確認

- [ ] PythonへcamelCase、`//`または`/** ... */`を適用していない。
- [ ] header、module構成、`main()`、呼出順および実行guardが規約どおりである。
- [ ] 工程fileとclass主体moduleのfile名・配置が規約どおりであり、関数主体folderへclassを混在させていない。
- [ ] 関数・method、class、定数、変数およびprivate methodの命名が規約どおりである。
- [ ] `str_`を使用せず、変数名が型だけでなく業務上の意味を表している。
- [ ] class見出し、関数見出し、設計IDおよび説明項目が定義上側にある。
- [ ] 関数内へ説明用docstringを重複記載していない。
- [ ] 全代入、loopおよび条件分岐に規定の日本語コメントがある。
- [ ] top-level間、method間、class直下、関数本体先頭および処理block間の空白行が規約どおりである。
- [ ] 対応する代入、keyword引数およびmappingの位置が必要範囲で揃っている。
- [ ] 引数とreturnへ式、関数結果、属性・要素またはliteralを規約外で直接記載していない。
- [ ] 変更した全関数・method・classを先頭から末尾まで確認した。
- [ ] 承認なしの旧API alias、wrapper、fallbackまたは二重実装がない。

## 6. 安全性、データおよび性能

- [ ] 型、例外、logger、path、外部入力および秘密情報の扱いを確認した。
- [ ] schema、型、null、順序、timezone、丸め、件数およびhashを確認した。
- [ ] 行単位処理、反復I/O、不要copy、再計算およびlibrary間変換を確認した。
- [ ] UI thread・event loopを停止する処理がなく、重い処理に進捗・取消し・失敗処理がある。
- [ ] 性能変更前後の機能、UI、値およびメモリを同一条件で確認した。
