# product_agent_rules

AI エージェント向けの開発・確認ルールを管理するためのリポジトリです。

複数バージョンの `.rules_*` ディレクトリを保持し、別プロジェクトでは必要なルールセットを `.rules` として取り込んで利用します。

## 使用準備

### 手順1. 取り込み先プロジェクトへルールを配置する

別プロジェクトへ取り込む場合は、`pull_rules.sh` を実行してください。

最新版の `.rules_v13` が、取り込み先リポジトリでは `.rules` という名前で配置されます。

### 手順2. AI エージェント用の指示を追加する

取り込み先プロジェクトの `AGENTS.md` など、AI エージェントが参照する指示ファイルには、以下を追加してください。

```markdown
- 開発・分析ルール
  - 開発または分析を行う場合、必ず`.rules/dev/rules_dev.md`を確認すること。
```

プロジェクト固有のルールは `.rules/dev/rules_dev_custom.md` に記載します。デフォルトは空です。`pull_rules.sh` でルールを更新しても、取り込み先にあるこのファイルの内容は保持されます。

## 使用方法

### 簡単な使用例

依頼前に、通常開発、簡易開発または分析を選びます。
v13 の通常開発では、最初に仕様書を作成・確認し、その後に要件定義、設計、実装、最終確認を行います。参照画像等を扱うapp開発では`ui-design`追加分類を使用します。

- `app`: アプリケーション向けの通常開発ルールです。仕様作成から実装後の最終確認までを扱います。
- `app + ui-design`: 参照画像、モックアップ、画面構造またはレスポンシブデザインを扱うapp開発です。再現度、UI要件ID、実装前プレビュー、画面比較およびユーザ目視承認を追加管理します。
- `batch`: バッチ処理やスクリプト向けの通常開発ルールです。仕様作成から実装後の最終確認までを扱います。
- `class`: クラス設計向けの通常開発ルールです。現在作成中のため、利用時は内容を確認してください。
- `quick_fix`: 既存仕様を変更しない軽微な修正向けの簡易開発ルールです。仕様変更や仕様書修正が必要な場合は使用できません。
- `analyze`: GitHub Actionsを原則として一括分析を行うルールです。全体ワークフロー、分割・並列、public/private分離、定期通知、終了予定およびChatGPT分析のGit管理を扱います。
- `performance`: 数値・大量処理に対する測定、pandas/NumPy/Polarsの選定、数値同値、チェックポイント、性能監査を扱う**横断追加ルール**です。`app`、`batch`、`analyze`を置き換えません。適用時は `.rules/dev/performance/` のルールとチェックリストを参照します。

依頼例:

```text
.rules/dev/rules_dev.md を確認してから進めてください。
今回は app ルールを使用します。
対象は sample_app です。
○○を作成したいです。
```

## ルールセットのバージョン管理

ルールセットの命名・更新は [RULE_VERSIONING.md](RULE_VERSIONING.md) に従います。

- ディレクトリ名は `.rules_v{n}` とし、`n`は1から始まる10進整数を使用します。
- `.rules_v01`のようなゼロ埋めは使用しません。
- GitHubの一覧は文字列順のため、`.rules_v10`が`.rules_v1`と`.rules_v2`の間に表示されることを許容します。
- 最新版は表示順ではなく、数値として最大のバージョン番号で判断します。

## ルールの取り込み

取り込み先のリポジトリで `pull_rules.sh` を実行します。

```bash
bash ./pull_rules.sh
```

既定では `yuki746289/product_agent_rules` から取得します。

### 取り込み対象

スクリプトを実行すると、取得元リポジトリにある `.rules_v13` の各項目が `.rules` へ配置されます。

```text
.rules_v13/* -> .rules/*
```

### 上書き確認

取り込み先に同名のファイルまたはディレクトリがある場合は、項目ごとに置換確認メッセージが表示されます。

```text
Replace '.rules/dev'? [y/yes/n/no]:
```

`y` または `yes` を入力すると、対象項目を削除してから `.rules_v12` の同名項目をコピーします。

`n` または `no` を入力すると、その項目をスキップして次の項目へ進みます。

### 注意

- `.rules` 直下の項目単位で置換されます。
- 取得元に存在しないローカル専用項目は保持されます。
- 置換をスキップした項目には、旧バージョンのファイルが残る場合があります。
- 取り込み後は `git status --short` や `git diff --stat` で差分を確認してください。
